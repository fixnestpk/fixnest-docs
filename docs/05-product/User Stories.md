## Purpose

This document translates FixNest business and operational needs into user-centered stories. Stories should guide feature prioritization, acceptance criteria, design decisions, and engineering planning.

## Homeowner Stories

### Booking and Discovery

- As a homeowner, I want to request a home service so that I can get help without searching for random technicians.
- As a homeowner, I want to select a service category so that FixNest understands what type of help I need.
- As a homeowner, I want to describe my issue with text, photos, or videos so that the technician can prepare before arriving.
- As a homeowner, I want to choose a preferred date and time window so that the visit fits my schedule.

### Pricing and Approval

- As a homeowner, I want pricing guidance before booking so that I understand likely costs.
- As a homeowner, I want to know whether an inspection fee applies so that I can decide before confirming.
- As a homeowner, I want to approve additional work before it starts so that I am not surprised by the final bill.
- As a homeowner, I want a digital invoice so that I have a record of what I paid for.

### Trust and Communication

- As a homeowner, I want technician assignment details so that I know who is visiting my home.
- As a homeowner, I want booking updates so that I know whether the technician is confirmed, delayed, or rescheduled.
- As a homeowner, I want a support contact so that I can get help if something changes.

### History and Support

- As a homeowner, I want service history and invoices so that I can track previous work.
- As a homeowner, I want to raise a complaint if the service fails so that FixNest can investigate and resolve it.
- As a homeowner, I want maintenance reminders so that I can prevent avoidable breakdowns in the future.

## Technician Stories

- As a technician, I want to receive jobs that match my verified skills and service area.
- As a technician, I want clear job details before accepting so that I can prepare properly.
- As a technician, I want customer location and contact instructions so that I can arrive on time.
- As a technician, I want to update job status so that operations and customers know what is happening.
- As a technician, I want to submit estimates for customer approval so that scope and payment expectations are clear.
- As a technician, I want completed work and ratings recorded so that I can build my reputation.
- As a technician, I want dispute notes documented so that my side of a service issue is recorded fairly.

## Operations Stories

- As an operations user, I want to assign technicians based on skill, location, availability, rating, and workload.
- As an operations user, I want to track job status from request to closure.
- As an operations user, I want complaint and refund records so that issues remain traceable.
- As an operations user, I want customer and technician profiles so that repeat bookings are easier to manage.
- As an operations user, I want reports on delays, complaints, revenue, and ratings so that service quality can improve.
- As an operations user, I want to pause or restrict technicians with quality issues so that customer trust is protected.

## Admin Stories

- As an admin, I want to manage service categories, pricing rules, and coverage areas so that the platform can adapt over time.
- As an admin, I want role-based access so that sensitive customer, technician, and financial data is protected.
- As an admin, I want audit logs for important changes so that operational decisions remain traceable.

## Future AI-Assisted Stories

- As a homeowner, I want guided troubleshooting so that I can identify the right service category.
- As a homeowner, I want estimated cost ranges based on issue details so that I can plan before booking.
- As operations, I want AI-assisted technician matching so that assignments are faster and more reliable.
- As operations, I want complaint themes summarized so that recurring process failures are easier to fix.

## Acceptance Criteria Template

Each story should eventually include:

- User role.
- Trigger or starting condition.
- Main flow.
- Alternate flows.
- Required data fields.
- Business rules.
- Error states.
- Success criteria.
- Analytics events.
